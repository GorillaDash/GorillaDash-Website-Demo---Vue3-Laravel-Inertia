# GD Client Inertia Starter

The GorillaDash client-site skeleton — a production-grade Laravel 13 + Inertia v3 +
Vue 3 SPA, extracted from the The Great Greek build. Every client-specific value has
been replaced with the neutral placeholder brand **"Juniper Table"** (slug `juniper-table`);
`bin/new-client.sh` renames the whole tree for a new client in one step.

## What's inside (beyond the Laravel starter kit)

- **Server-driven SPA** — Inertia v3, pages in `resources/ts/pages/`, props as the
  data contract; SSR via a dedicated entry (`resources/ts/ssr.ts`) that serializes
  the Apollo cache into `<head>`; served by Octane/FrankenPHP in production.
- **Runtime multi-locale** — `APP_LOCALES` env picks the locale set per deployment;
  a single build serves every country. `/{locale}` prefixes exist only on
  multilingual deployments; the frontend re-attaches them at runtime
  (`localizedUrl()`, `<LocaleLink>`). Tolgee i18n config is runtime, per country.
  See the `add-locale` skill.
- **CMS-renamable page paths** — top-level routes use a `{page}` parameter with a
  reserved-segment guard, so the CMS can rename `/locations` → `/stores` per locale
  with zero code changes and `route:cache` intact. Typed route names/params are
  generated by `php artisan cms-routes:types` (Wayfinder-style, gitignored).
  See `docs/cms-dynamic-page-paths.md` and the `add-cms-route` skill.
- **GorillaDash data layer** — `gorilladash/laravel-website-sdk`: server-side OAuth,
  same-origin `/graphql` proxy with SWR caching, cache-clear webhook; typed Apollo
  documents via graphql-codegen (`pnpm run codegen`).
- **Cloudflare edge-cached HTML** — `EdgeCacheGuestPage` + `EdgeCacheGrant` grant
  a shared copy per response; `DropEmptyGuestSession` keeps guests cookie-free so
  they stay on the edge; the bound-store selection lives in a browser-written
  cookie, not the session. Cache Rules in `deploy/cloudflare/` converge via CI,
  and verify themselves against the live host before they are kept.
  See `docs/edge-html-cache.md` and `docs/session-bound-location.md`.
- **Public forms, without losing the edge cache** — the starter ships no form, but
  it ships the shape one has to have here: a stateless `api` route (a CSRF prime
  would start a session and take that visitor off the edge), Precognition so one
  `FormRequest` serves both the live per-field validation and the submit, and
  reCAPTCHA v3 + an intent-keyed throttle + a honeypot in place of the token.
  See `docs/public-forms.md`.
- **One API response envelope** — every JSON body a site authors goes through
  `flugger/laravel-responder` via an `Api\Controller` base class, with error
  messages resolved from a code out of `lang/en/errors.php`. Not shipped: the
  package needs a VCS pin on Laravel 13 (upstream caps at 12), and the envelope
  must never swallow validation's 422 or the precognitive forms lose every
  inline error. See `docs/api-responses.md`.
- **GKE deployment** — one multi-stage Dockerfile builds `web` (FrankenPHP) +
  `ssr` (Node) sidecar images from the same SHA; Kustomize base + per-country
  overlays; Workload Identity for Cloud SQL; Cloud Armor origin lockdown;
  deploys via `make ship` or the GitHub Actions `deploy` workflow (WIF OIDC).
  See `deploy/README.md` and `deploy/CHECKLIST.md`.
- **Performance discipline** — fonts through the Vite fonts pipeline with
  metric-matched fallbacks (zero CLS), images on GCS/CDN via `@/lib/gcs.ts`
  helpers (never bundled), load-test scripts in `load-tests/`.
  See `docs/perf-mobile-pagespeed.md` and the `lighthouse-pagespeed` skill.
- **Tests that guard the architecture** — Pest suites cover dynamic routing,
  locale routing, edge-cache headers, bound location, and the frontend path layer
  (`tests/js/pagePaths.test.ts`, run by Pest).

## Starting a new client site

```bash
# 1. Create the client repo from this template and clone it:
gh repo create GorillaDash/<Client>-inertiajs --private \
  --template=GorillaDash/gd-client-inertia-starter --clone
cd <Client>-inertiajs

# 2. Rename the Juniper Table placeholder brand in one step:
bin/new-client.sh --slug great-burger --name "Great Burger" --domain greatburger.com

# 3. Confirm the baseline is still green, then commit the rename:
composer setup && composer ci:check
git add -A && git commit -m "chore: rename starter placeholders to <Client>" && git push

# 4. Work through the onboarding checklist (GD CMS, Tolgee, GCP, Cloudflare, fonts):
open docs/NEW-CLIENT-CHECKLIST.md   # 中文版: docs/NEW-CLIENT-CHECKLIST.zh-TW.md
```

The starter ships one market, `usa` (which is also the frontend's hardcoded
fallback), so step 2 needs no country argument. Add further markets later, one
overlay at a time — see _Adding a new country_ in `deploy/README.md`:

```bash
bin/new-country.sh --country au --locales en-AU --domain au.greatburger.com --tz Australia/Sydney
```

`--locales` is the one to get right: it writes `APP_LOCALES`, which is what turns on the
`/{locale}` prefix and the language switcher. `APP_LOCALE` (Laravel's `lang/` lookups) is
derived from it and is _not_ what makes a site French.

## Local development

```bash
composer setup    # install, .env, key, migrate, pnpm build
composer dev      # php serve + queue + pail + vite
composer ci:check # full CI gate: oxlint + prettier + vue-tsc + pint + pest
```

The site runs without GorillaDash credentials (CMS lookups fail soft), but real
page content needs `GD_*` values in `.env` — see `.env.example` comments.

## Placeholder inventory

Everything client-specific is spelled `juniper-table` / `Juniper Table` / `juniper-table-usa.example.com`
so it is greppable. The main sites (all handled by `bin/new-client.sh`):

| Placeholder                                | Where                                                                                                                                                          |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Juniper Table` (display name)                | `.env.example`, overlay `config.env`, UI copy                                                                                                                  |
| `juniper-table` (slug)                              | `Makefile`, k8s manifests, namespaces, secrets, image repo, static-IP name                                                                                     |
| `juniperTable_` (GCS prefix: camelCase slug + `_`) | `package.json static:upload`, `.env.example`, overlay `config.env`, `lib/gcs.ts`, `app.blade.php` — bucket + naming rules in `docs/NEW-CLIENT-CHECKLIST.md` §4 |
| `juniper-table-usa.example.com`                     | `constants/navigation.ts`, `tests/js/pagePaths.test.ts`, `deploy/*.md`                                                                                         |
| Empty `GD_*`/`TOLGEE_*`/map keys           | overlay `config.env` — fill per client                                                                                                                         |

> **`--domain` does not reach Kubernetes.** The overlay's `APP_URL` and the Ingress
> `host:` are `juniper-table-usa.gorilladashstaging.com` — a _staging_ host, so the **slug** rule
> renames it (`<slug>-usa.gorilladashstaging.com`), not `--domain`. Point them at the real
> apex by hand at go-live, once DNS and the Cloudflare zone exist.
